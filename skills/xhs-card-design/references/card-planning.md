# 配图规划：每张图放什么、怎么排

视觉风格见 `styles.md`。本节只讲「每张放什么」，不讲配色和字体。

## 按选题排图

| 选题 | 图数参照 | 顺序与每张内容 |
|---|---|---|
| 概念解释 | 1 张关系图起步，关系多再加 | 首张放模块图或关系图，正文补定义与条件 |
| 功能总览 | 按功能模块分页 | 标题页 → 功能分区网格 → 续分区；版本时间写正文 |
| 自动化实录 | 按材料多少定，可很长 | 系统图或结果 → 人工介入点 → 过程长页 |
| 操作教程 | 按步骤定位入口 | 界面截图框出具体入口，标出选项名 |
| 引文解读 | 原句页 → 解释页 | 原句、出处、自写解释分层 |
| 新闻事件 | 按材料定 | 官方公告截图 → 外部反应截图 → 受影响界面截图 |
| 单条社媒帖解读 | 0 或 1 个媒体 | 有可核对结果才配：成品、结果图或演示 |

图数与互动没有固定最优解；材料够才加页，不为凑页重复正文。

## 封面

| 类型 | 用法 |
|---|---|
| 排名表、流程图或模块图 | 首选，信息本身就是封面 |
| 原帖 / 公告截图 | 新闻或引文类可用，截图铺满 |
| 实际结果、产品实物 | 有成品时用 |
| 大标题文字卡 | 无图材料时备用 |
| 人物口播首帧、插画角色封面 | 默认不借；除非账号本身出镜或有角色设定 |
| 视频黑窗 | 不当封面 |

## 图卡与正文分工

适用于小红书图文。方法参考多家账号的公开笔记结构归纳，不是平台官方规律。

1. **先定主阅读面。** 概念、原理、科普类：定义、机制、例子和前提条件写在图卡上，读者只翻图也能看懂；正文只抛问题、点名概念、交代来源、给一句可动手的建议。新闻、工具、功能类：图放截图、对比和关系，正文补版本时间、权限、额度和适用条件。
2. **封面写对象＋主张。** 一眼看出讲谁、讲什么结论，信息本身当钩子，不吊空悬念。
3. **图卡一页推进一步。** 常用顺序：给现象命名 → 对照或机制 → 例子 → 方法或检查。主卡形式按材料选：对话场景、左右对照、编号清单、研究小框、流程图都行；内容简单就少做几页，不为凑页加流程箭头。
4. **重复只留关键结论。** 不把图里整段搬进正文；关键结论可在正文再概括一次。会改变理解的前提条件与结论放同一页。
5. **结尾不强求。** 末页可以留一个具体问题或核验动作，也可以直接结束；不凑金句总结卡。
6. **原句、出处、自写解释分层**；截图铺满；官方原文放最后作附录；高密度小字号见 `../SKILL.md`。


## 素材选用

| 素材 | 何时用 |
|---|---|
| 截图 | 新闻、引文、操作入口；放大铺满，不留上下白边 |
| 原帖图 | 转述外站发布时放第一张，保留作者与时间 |
| 对比表 | 多个工具或版本逐项比较，每格回查材料 |
| 流程图 | 讲 Agent 分工、路由、人工介入点 |
| 结果图 | 有自己或原作者的产出时，放在说明之前 |

配图标题直接写信息，不用聊天口吻。
