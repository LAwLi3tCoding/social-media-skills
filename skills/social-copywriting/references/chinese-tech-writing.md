# chinese-tech-writing 规则摘要（用于小红书 / X 技术文案）

来源：fwqaaq/chinese-tech-writing（MIT，v1.1.0，基于 ruanyf/document-style-guide）。本地只读副本位置见用户的偏好层（如有）。本摘要只留适用于社媒短文的规则。

## 一、可复用规则

**空格**
- 中文和英文之间加一个半角空格（Codex 文档、改 skill 的 agent）。
- 中文和数字之间可以加空格，也可以不加，但全文统一。社媒稿统一加空格（4 个基准、2026 年 8 月）。
- 数字和单位之间加空格（16 GB）；百分号紧贴数字（63.7%）。
- 英文、数字和全角标点之间不加空格（MacBook Air。）。全角括号前后不加空格。

**标点**
- 中文句子一律用全角标点；整句英文才用半角。
- 中文里的并列词用顿号，包括夹在中文里的英文词（Claude Code、OpenAI Codex）；最后一项用「和」连接更顺。
- 不要一逗到底：一句里讲了两件事就用句号断开，条件和后果之间可以用分号。
- 括号注释在句末时，句号放在括号外。
- 中文省略号写「……」，不和「等」叠用。技术文案不用感叹号，更不连用。
- 时间、比例、版本号用半角冒号（16:9）。
- 句号、逗号、顿号、冒号等点号不放在行首，也不放在标题末尾。

**数字**
- 一律用半角阿拉伯数字。五位及以上加千分位（15,000）；年份、编号、版本号不加。
- 数值范围用「~」（或一字线），全文统一，前后单位一致（10~40、+3.3~12.0）。不混用 en dash「–」。
- 「增加了」表示增量，「增加到」表示定量；不写「降低 N 倍」，改写成降低百分之几或「从 A 降到 B」。

**句子**
- 单句（不含标点）最好在 20 字以内，30~39 字要保证意思清楚，超过 40 字就拆。逗号连起来的整句不超过 100 字。
- 优先用简单句和并列句；名词前的修饰不超过两层。
- 优先用主动语态；施事不明或受事更重要时可以用被动（「skill 退回上一版」）。
- 优先用肯定句，不用双重否定。
- 不用口语化、非正式的词（「塞进」写成「放进」），也不用生造的文言式表达（「唯二」）。
- 代词必须指向唯一的对象。「它」「其」「这」有歧义时写出名词（「它测的是」写成「论文测的是」）。
- 的、地、得按词性区分。

**英文词**
- 英文专有名词按官方写法大写（Markdown、Python）；普通名词不大写（agent、skill、wiki）。
- 缩写第一次出现时，在括号里给全称或中文解释，后文直接用缩写。
- 英文文章名、书名译成中文时，改用书名号。

**段落**
- 一段只讲一个主题，中心句放在段首。
- 段落控制在 7 行以内，最好在 4 行以内；段与段之间空一行，开头不缩进。

## 二、审稿流程

1. 先备份：`<文件>_pre_ctw.txt`；有卡片时同时备份 `cards/`、`cards_src/`、`covers/` 和预览图。
2. 跑机器检查：把正文、X 文案各复制成 `.md`，然后执行 `node <chinese-tech-writing>/scripts/lint.mjs <文件>.md`（clone 路径见用户的偏好层）。它会报：中英文空格、全角数字、省略号、感叹号连用、千分位、句长超过 40 字。`--fix` 不要直接用于终稿，改动要逐条人工确认。
3. 人工逐条过：拿第一节的规则逐条对照标题、正文、X 文案和卡片文字。卡片文字从 HTML 源（`cards_src/gen.py` 或 `0*.html`）里抽出来读。
4. 写 `<稿目录>/style_review.md`，表格一行一条：位置、原文、命中规则、已改或未改、理由。
5. 只改措辞和排版，不改事实、数字和结论；用户的禁用句式照常遵守。
6. 复核：
   - 再跑 lint.mjs，以及 `lint_copy.py`（`--title/--body/--tags/--profile`，卡片和 X 用 `--text`）。
   - 用 Python `len()` 确认「正文 + 话题 ≤1000」。
   - 卡片有改动时：重新渲染，运行 `check_cards.py`，切块检查文字离边框至少 12px，重建预览图。
   - X 文案有改动时：重新生成 intent 链接，编码用 `quote(text, safe='/')`。

## 三、与用户规则的冲突及处理

| 外部规则 | 冲突 | 处理 |
|---|---|---|
| 标题里中英文之间也要加空格 | 小红书标题 ≤20 字，按平台算法，半角字符（含空格）两个算一个字 | 标题按平台字数走，lint_copy 超过 20 字就不加空格；正文、卡片和 X 照常加空格 |
| 普通名词不大写 | 标题里 Agent、Skill 可能是搜索关键词，系列写法见偏好层 | 标题保留系列写法（见偏好层）；正文和卡片统一小写 |
| 缩写首次出现要写英文全称和中文译名 | 用户规则：准确术语保留（PR、lint、harness），术语就地用白话解释，不堆括号 | 只给读者不熟的术语加一句白话解释（system prompt、验证集）；常见术语不展开全称 |
| 单句不超过 40 字，并且要拆分 | 小红书正文 ≤1000 字；卡片版面是固定格子 | 正文优先把逗号换成句号或分号，不增加字数；卡片说明已用分号断开的长句不再拆，并在审稿表里写明理由 |
| 优先用肯定句、主动语态 | 「作者推测」是来源原话，且已经核查 | 事实和来源原话优先，不改写 |
| 数字统一写成阿拉伯数字 | 卡片大字号小标题里，10 以内的计数用汉字更醒目，编号旁写阿拉伯数字会粘连 | 数据行一律用阿拉伯数字；小标题里 10 以内的计数可以用汉字（「五个模型」） |
| 标题层级、文件命名、文档体系 | 小红书和 X 正文不用 Markdown 标题 | 不适用；长文小节标题按用户规则写成陈述句，不用问句 |
| （外部没有这条） | 用户禁用句式见 social-copywriting 和偏好层 | 用户禁用项优先，审稿时同时查 |
