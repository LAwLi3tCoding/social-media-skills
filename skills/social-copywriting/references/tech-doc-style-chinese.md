# Fenng 中文技术写作规则摘要（用于小红书 / X 技术文案）

来源：Fenng/Tech-Doc-Style-Chinese（MIT，skill 名 `tech-doc-style-chinese`）。仓库：https://github.com/Fenng/Tech-Doc-Style-Chinese。本地只读副本位置见用户的偏好层（如有）。

这是小红书和 X 技术文案的**主规范**。fwqaaq/chinese-tech-writing 只保留 `scripts/lint.mjs`，用来检查能机械判定的排版问题。用户规则（social-copywriting、偏好层、标题字数、1000 字上限、禁用句式）和已核查的事实，一律优先于本摘要。

不要套用 Fenng 里这两条：默认不称呼读者；按手册 / 入口页 / 操作步骤来组织短帖。

## 一、适用于短技术文案的规则

**事实保真（最高优先级）**

- 不补充来源里没有的日期、数字、时限、能力、条件或结论。
- 不删除限制、例外、失败处理和适用范围。
- 不把「可能」「通常」「计划」「作者推测」改成定论。
- 资料不够就保留原意，或标明待确认，不要自行补全。

**术语**

- 同一概念全文用同一个首选词。不为了避免重复而换同义词。
- 产品名、字段名、路径、命令、代码保持官方写法或原文，不翻译、不改大小写（API、ChatGPT、SKILL.md、name、description）。
- 「该」「其」「此」「上述」「它」有歧义时，写成具体名称。

**语气**

- 准确先于修辞，清楚先于热闹。直接写是什么、适用于什么、读者能做什么。
- 删掉问候式开场、宣传口号、空泛形容，以及「赋能」「抓手」「闭环」「打通」「沉淀」这类黑话。
- 删掉不增加信息的铺垫，例如「要注意两点」「一种实用延伸是」。改成直接陈述。
- 可以用「你」或「自己」，这是短帖口吻，不按 Fenng 文档默认改成无主句。

**句子与结构**

- 一段一个主题。一句保持一个清楚的主干，不要把条件、动作、例外堆在同一句里。
- 列表项的层级、句式、信息密度保持一致。
- 小标题用陈述句，不用问句。标题说明用途，不用抽象名词单独成题。
- 不要为了更短或更整齐，删掉事实、条件或例外。
- 不要把短帖改成「简介 → 快速上手 → API → FAQ」这种手册目录。

**排版**

- 中文和英文、阿拉伯数字、版本号之间加一个半角空格（使用 API、等待 3 秒、版本 2.0）。中文和行内代码之间同样加空格。
- 英文、数字和全角标点之间不加空格。全角标点前后不加空格。
- 数字与半角单位之间加空格（10 GB、200 ms）；百分号、角度符号紧贴数字（50%、90°）。
- 中文日期写成「2026 年 8 月」；时间内部不加空格（15:30）。
- 中文句子用全角标点。正文里如需引号，可用直角引号「」；社媒稿不额外加引号，卡片上已有加粗或其他强调时，不必再套「」。书名、文档名用书名号《》。
- 确定错词要改：阀值 → 阈值，布署 → 部署，做为 → 作为，截止某日 → 截至某日（「截止日期」可保留）。

**通常用不上的部分**

- API 状态词译法、按钮 / 空状态文案、操作手册和故障排查模板、受控中文的完整步骤格式，只在写产品文档或操作说明时再读原仓库 `references/`。
- Fenng 的 lint 不检查中英空格、省略号、全角数字；这些走 fwqaaq 的 `lint.mjs`。

## 二、审稿流程

按 Fenng 的「审阅」模式：先列问题，再改稿。未经允许，不改事实和数字。

1. 备份：文案存为 `<文件>_pre_fenng.txt`；有卡片时同时备份 `cards/`、`cards_src/`、`covers/` 和 `cards_preview.png`。
2. 通读标题、正文、X 文案和卡片文字（从 `cards_src/gen.py` 或 `0*.html` 抽出可见文本）。对照第一节的规则，以及用户的禁用句式。
3. 跑两套机器检查（先把正文、X 文案复制成 `.md`，避免脚本扫到整个目录；clone 路径见用户的偏好层）：

```bash
python3 <Tech-Doc-Style-Chinese>/scripts/lint_copy_rules.py --strict body.md x.md title.md

node <chinese-tech-writing>/scripts/lint.mjs --no-color body.md x.md title.md
```

Fenng 的脚本查错词、术语大小写、弯引号、不宜使用的称呼和黑话等。fwqaaq 的脚本查中英空格、省略号、全角数字、连用感叹号、千分位、句长；`--fix` 不要直接打在终稿上，改动要逐条确认。

4. 把命中项写入稿目录里的 `style_review.md`，一行一条：位置、原文、规则、已改或未改、理由。
5. 只改措辞、术语和排版。改完再跑上面两套检查，并跑用户规则检查：

```bash
python3 <social-copywriting>/scripts/lint_copy.py \
  --title title.txt --body body.txt --tags tags.txt \
  --profile <偏好层>/SKILL.md

python3 <social-copywriting>/scripts/lint_copy.py \
  --text x.txt --profile <偏好层>/SKILL.md
```

6. 用 Python `len()` 确认「正文（去掉末尾换行）+ 一个空格 + 话题 ≤1000」。标题按 `lint_copy.py` 的平台字数，不超过 20。
7. 卡片有改动时：重新渲染，运行 `check_cards.py`，用 `edges.mjs` 检查文字距边框至少 12px，再切块目视确认，重建 `cards_preview.png`。若改了卡片 01，把它复制为约定的封面文件。
8. X 文案有改动时：重做 intent 链接，编码用 `quote(text, safe='/')`。

## 三、与用户规则的冲突及处理

| 外部规则 | 冲突 | 处理 |
|---|---|---|
| 默认不直接称呼读者，少用「你」「您」 | 小红书和 X 的技术短文常用「你」或「自己」，口吻更直接 | 不采用。短帖可以称呼读者；不要因此改成公文无主句 |
| 按手册、入口页、API、FAQ 组织内容 | 小红书正文加话题 ≤1000 字，X 是短帖，还有卡片版面 | 不采用手册式结构。按社媒稿已有骨架写：先说是什么，再讲机制、数据和限制 |
| 中英文之间必须加空格（Fenng 正文规则，fwqaaq lint 也会报） | 小红书标题 ≤20 字，半角字符（含空格）两个算一个字 | 标题以平台字数为准，lint_copy 超 20 就不加空格；正文、卡片、X 照常加空格 |
| 普通中文的数值范围优先写「至」 | 短帖和卡片用「~」更省版面 | 短帖和卡片继续用「~」，全文统一；不改数字本身 |
| 中文引号用「」 | 社媒稿不必给每个术语加引号；允许「」本身，但不要写成转述框架 | 需要引用或标界面名时可以用「」；不额外加。卡片已有加粗时不再套引号 |
| 缩写首次出现给全称 | 用户规则：准确术语保留，用白话解释，不堆括号 | 只给读者可能不熟的术语加一句解释（system prompt、验证集）；常见术语不展开 |
| Fenng lint 可能提示「你」或风格项 | 短帖允许称呼读者 | 不用 `--strict` 当否决「你」的理由；称呼问题按本节处理 |
| 句子尽量短、条件单独拆开 | 1000 字上限和卡片格子限制行数 | 正文优先把逗号改成句号或分号，尽量不增字；卡片上已用分号断开的长句不再拆，并在审稿表写明 |
| （Fenng 没有相反的禁止） | 用户禁用句式见 social-copywriting 和偏好层 | 用户禁用项优先，审稿时同时查 |
| 不改变「推测」「可能」等确定程度 | 与「优先肯定句」可能打架 | 来源里的推测、限制、未测项必须保留，不当成自我削弱措辞删掉 |

合并进 `social-copywriting/references/` 时，本文件管「事实、术语、语气和审稿流程」；`chinese-tech-writing.md` 里可复用的空格、标点和句长规则仍有效，检查命令以本文第二节的双 lint 为准。
